## Пользовательские сценарии

### [ Сценарий 1 - Выбор токена и запуск анализа ]

1. Пользователь открывает RugShield в браузере.
2. Пользователь вводит адрес токена в сети Solana и запускает анализ.
3. Система проверяет формат адреса и ищет токен. Если адрес введён неверно или токен не найден, система сообщает об этом и предлагает проверить адрес.
4. Если токен найден, система запрашивает данные о цене, объёме торгов и транзакциях в блокчейне. Во время загрузки она показывает, что анализ выполняется.
5. После загрузки открывается страница токена. На ней доступны рыночные показатели, результаты анализа тренда и оценка риска. Если часть данных недоступна, система действует по сценарию 5.

### [ Сценарий 2 - Просмотр данных о токене ]

1. Пользователь открывает данные на странице выбранного токена.
2. Система показывает динамику цены и объёма торгов, указывает период наблюдения и выводит сводку по переводам токена между кошельками за тот же период.
3. Пользователь может сопоставить изменения рыночных показателей с активностью кошельков и перейти к оценке тренда или риска.

### [ Сценарий 3 - Просмотр оценки тренда ]

1. Пользователь открывает раздел с оценкой тренда.
2. Система показывает текущее направление движения цены за анализируемый период: восходящий тренд, нисходящий тренд или отсутствие выраженного тренда.
3. Система объясняет, какие изменения цены и объёма торгов повлияли на вывод, и показывает данные о переводах между кошельками, если они учитывались при расчёте.
4. Если система обнаружила признаки возможного изменения тренда, она показывает их рядом с текущей оценкой и поясняет, какие данные на них указывают.

### [ Сценарий 4 - Просмотр оценки рыночного риска ]

1. Пользователь открывает раздел с оценкой риска на странице токена.
2. Система показывает уровень риска и перечисляет признаки, которые повлияли на него.
3. Пользователь читает пояснение. Например, если резкое изменение цены совпало с необычной активностью крупных держателей, система показывает, какие изменения цены, объёма торгов и переводов были зафиксированы за этот период.
4. Пользователь может вернуться к исходным показателям на странице токена и посмотреть, на каких данных основана оценка.

### [ Сценарий 5 - Обработка неполных данных или сбоя источника ]

1. При временной недоступности внешнего API система повторяет запрос и при необходимости обращается к резервному источнику.
2. Если данных всё равно недостаточно, система указывает, какие сведения отсутствуют и какую оценку из-за этого нельзя рассчитать.
3. Если данных хватает для одной из двух оценок, система показывает её. Например, пользователь может увидеть текущий тренд по рыночным данным, даже если оценка риска пока недоступна из-за неполной истории транзакций.
4. Пользователь может повторить запрос позже или выбрать другой токен.
